# L860-GL-16 на OpenWrt 25: диагностика и исправления

Этот документ описывает реальные проблемы, найденные при установке Fibocom
L860-GL-16 на OpenWrt 25.12.5, и порядок диагностики, который позволяет не
путать неисправность SIM, неправильный APN и сбой XMM/NCM.

## Проверенная конфигурация

- OpenWrt 25.12.5, `mediatek/filogic`, `aarch64_cortex-a53`;
- Fibocom L860-GL-16 / Intel XMM7560, USB ID `8087:095a`;
- `xmm-modem 0.1.7-r1`, `luci-proto-xmm`;
- три обычные SIM: Beeline, MegaFon и T2;
- физическая SIM в единственном слоте M.2-адаптера.

Абонентские идентификаторы из диагностических выводов намеренно не
публикуются.

## Что оказалось неверным в исходной диагностике

Сообщение `Carrier: Absent` не означает автоматически неправильный APN.
Подключение проходит несколько независимых стадий:

```text
USB 8087:095a
  -> /dev/ttyACM0 и wwan0
  -> SIM READY
  -> регистрация CEREG 1/5
  -> PDP-контекст и выбранный сетью APN
  -> адрес/маршрут/DNS в OpenWrt
  -> реальный трафик
```

APN влияет только после того, как SIM прочитана и модем зарегистрирован.

## 1. Модем отвечает, но сообщает `SIM NOT INSERTED`

Наблюдавшиеся ответы:

```text
AT+CPIN?
+CME ERROR: SIM NOT INSERTED
```

В таком состоянии также не читаются IMSI и ICCID. Изменение APN бесполезно:
модем электрически не видит карту.

Решение:

1. Полностью обесточить M.2-адаптер.
2. Извлечь и заново ровно установить физическую SIM.
3. Проверить контакты и ориентацию карты.
4. Включить адаптер и дождаться повторного USB-перечисления.
5. Убедиться, что `AT+CPIN?` возвращает `+CPIN: READY`.

У L860-GL-16 есть внутренний eSIM-интерфейс. На обычном адаптере с одним
физическим SIM-слотом не следует переключаться на вторичный слот: он может
показывать неинициализированное состояние `SIM PIN REQUIRED`, хотя физическая
SIM находится в слоте 0.

Проверить PIN без попытки разблокировки:

```sh
sms_tool -d /dev/ttyACM0 at 'AT+CPIN?'
sms_tool -d /dev/ttyACM0 at 'AT+CLCK="SC",2'
```

`+CLCK: 0` означает, что проверка PIN отключена.

## 2. Неправильный параметр PDP в UCI

Версия XMM-handler, проверенная на OpenWrt 25.12.5, объявляет и читает параметр
`pdp`, а не `pdptype`:

```sh
uci set network.LTE_Fibocom_860.pdp='IP'
uci -q delete network.LTE_Fibocom_860.pdptype
uci commit network
```

Исходный установщик записывал `pdptype='IPV4V6'`. Handler игнорировал его и
молча переходил к своему значению по умолчанию `IP`. Исправленный установщик
сразу создаёт корректный `pdp='IP'`.

## 3. `/dev/ttyACMx` — это шаблон, а не имя устройства

Команду с буквой `x` нельзя выполнять буквально:

```text
/dev/ttyACMx
```

Она записывает в 3ginfo несуществующий путь. Используйте порт, который реально
ответил на `AT+CGMM`/`AT+CPIN?`, обычно `/dev/ttyACM0`:

```sh
uci set 3ginfo.@3ginfo[0].device='/dev/ttyACM0'
uci commit 3ginfo
/etc/init.d/uhttpd restart
```

Неверный порт 3ginfo ломает отображение телеметрии, но не обязательно сам
сетевой интерфейс XMM: это две отдельные настройки.

## 4. Автоматический APN

Для обычной LTE-SIM правильнее сначала не передавать APN. Оператор выбирает
Default APN из профиля абонента. В UCI это выглядит так:

```sh
uci set network.LTE_Fibocom_860.apn=''
uci commit network
```

Проверено после нового PDP-подключения:

| SIM | APN, назначенный сетью | Результат |
|---|---|---|
| Beeline | `internet.beeline.ru` | IPv4, DNS, ping |
| MegaFon | `internet` | IPv4, DNS, ping |
| T2 | `INTERNET.TELE2.RU` | IPv4, DNS, ping |

Посмотреть фактически выбранный сетью APN:

```sh
sms_tool -d /dev/ttyACM0 at 'AT+CGCONTRDP=1'
```

Явный APN всё ещё можно ввести при установке для корпоративной, частной или
нестандартно настроенной SIM.

## 5. Модем не поднимается после перезапуска USB-адаптера

L860-GL-16 является составным USB-устройством. При включении он сначала кратко
появляется, сбрасывается, а затем создаёт три ACM- и три NCM-интерфейса.
Пакетный `/etc/hotplug.d/usb/01_xmm.sh` иногда запускает netifd слишком рано.
Дополнительные события `add` способны наложить новый `ifup` на ещё не
завершившийся `xmm-disconnect`; тогда интерфейс получает адрес, но `wwan0`
через несколько секунд теряет carrier.

Файл [`files/99-l860-autostart`](../files/99-l860-autostart):

- блокирует ранний запуск на время перечисления USB;
- отсекает повторные события одного подключения;
- дожидается завершения старого teardown;
- после паузы выполняет один чистый `ifup`;
- не требует перезагрузки всего роутера при замене SIM.

Установщик размещает его автоматически. Ручная проверка:

```sh
logread -e l860-hotplug
ifstatus LTE_Fibocom_860
ip link show wwan0
ping -I wwan0 -c 5 1.1.1.1
```

Рабочее состояние должно одновременно содержать:

```text
ifstatus: "up": true
ip link:  UP,LOWER_UP
ping:     0% packet loss
```

Одного адреса в `ifstatus` недостаточно: после падения carrier старый адрес
может некоторое время оставаться в состоянии netifd.

## 6. Правильный порядок диагностики

Исправленная версия устанавливает команду:

```sh
l860-healthcheck
```

Вручную те же стадии проверяются так:

```sh
ls -l /dev/ttyACM*
sms_tool -d /dev/ttyACM0 at 'AT+CGMM'
sms_tool -d /dev/ttyACM0 at 'AT+CPIN?'
sms_tool -d /dev/ttyACM0 at 'AT+COPS?'
sms_tool -d /dev/ttyACM0 at 'AT+CEREG?'
sms_tool -d /dev/ttyACM0 at 'AT+CGCONTRDP=1'
ifstatus LTE_Fibocom_860
ip link show wwan0
ping -I wwan0 -c 5 1.1.1.1
```

Интерпретация регистрации:

- `+CEREG: ...,1` — домашняя сеть;
- `+CEREG: ...,5` — роуминг;
- `+CEREG: ...,0` — не зарегистрирован;
- `+COPS: 2` — модем отключён от оператора или ещё не начал регистрацию.

Не публикуйте полный вывод `AT+CIMI`, `AT+CCID` или `AT+CGSN`: это IMSI,
ICCID и IMEI.

## 7. Прочие сообщения

- `Failed add repository modem_kmod!` от `add.sh` 132lan не помешал установке:
  `xmm-modem` и `luci-proto-xmm` были установлены из доступного фида.
- `sh: missing ]` от backend 3ginfo-lite наблюдался вместе с корректным JSON.
  Это ошибка shell-проверки внутри панели, а не признак падения модема.
- Несогласованные ответы AT обычно означают, что netifd и ручной `sms_tool`
  одновременно используют один ACM-порт. Для чистой диагностики временно
  остановите только LTE: `ifdown LTE_Fibocom_860`.

## 8. IPv6 / dual-stack (`pdp='IPV4V6'`)

Проверено 2026-09-18 на L860-GL-16 (прошивка `18601.5001.00.01.16.48`),
OpenWrt 25.12.5, SIM MegaFon (`apn='internet'`).

**Как устроено.** XMM-handler ведёт данные через PDP-контекст `profile`
(по умолчанию CID 1). Attach-контекст модема (CID 0) отдельный: прошивка не
даёт его удалить (`AT+CGDCONT=0` → `operation not allowed`) и не открывает на
нём канал данных (`AT+CGDATA="M-RAW_IP",0` → `operation not supported`).
С `pdp='IPV4V6'` handler создаёт `AT+CGDCONT=1,"IPV4V6","<apn>"` и после
подъёма запускает dhcpv6-подынтерфейс `LTE_Fibocom_860_6`, который берёт
префикс /64 из RA модема.

**Что делает оператор.** MegaFon отвечает на запрос IPv4v6 для этой второй
PDN-сессии случайным образом: примерно в половине активаций выдаёт только
IPv4. Это решение сети, а не модема — измерено 12 активациями подряд с
чистым AT-портом (6/12 с IPv6), с attach-контекстом и IPv4, и IPv4v6.
Признаки IPv4-only активации:

```sh
AT+CGCONTRDP=1        # одна строка (только IPv4) вместо двух
ubus call network.interface.LTE_Fibocom_860_6 status | jsonfilter -e '@["ipv6-prefix"][*].address'
                      # пусто или "::"
```

Если IPv6 выдан, префикс появляется в течение ~50 с после `ifup`, а трафик
IPv6 начинает ходить ещё через ~45–60 с — это тоже поведение сети.

**Что делает этот fork.** `files/99-l860-dualstack` ставится в
`/etc/hotplug.d/iface/` и работает только при `pdp` `IPV4V6` или `IPV6`:
после каждого `ifup` он ждёт префикс до 75 с и, если его нет, выполняет
`ifup` ещё раз — не более 5 раз подряд, полученный префикс сбрасывает
счётчик. Обычно хватает одной переактивации (~2 мин до полного dual-stack,
в том числе после перезагрузки роутера). Проверка:

```sh
logread -e l860-dualstack
```

**Переключение режима.** `uci set network.LTE_Fibocom_860.pdp='IPV4V6'`
(или `'IP'`), `uci commit network`, `ifup LTE_Fibocom_860` — либо LuCI →
Network → Interfaces → LTE_Fibocom_860 → Edit → PDP Type. Хук читает `pdp`
при каждом `ifup`; при `IP` он ничего не делает. На SIM без IPv6 держите
`IP`: запрос IPv4v6 сам по себе безвреден (сеть выдаст IPv4), но хук не
отличит «оператор без IPv6» от «не повезло» и будет переподключать PDN
до 5 раз при каждом подъёме.

**Чего не будет.** MBIM у L860-GL существует только в PCIe-режиме (драйвер
`iosm`, ThinkPad); в USB-композиции 8087:095a MBIM-интерфейса нет, а
`AT+GTUSBMODE`, `AT+XUSBCFG`, `AT+XUSBCOMP` в этой прошивке не реализованы.
Перевести USB-модуль в MBIM нельзя. Также не помогает смена attach-контекста
на `IPV4V6` (`AT+CGDCONT=0,"IPV4V6","internet"`, сохраняется в NV модема):
IPv6 на CID 0 появляется, но данные через него не идут, а вероятность
IPv6 на CID 1 не меняется. `profile='0'` даёт `NO-CARRIER`.

## Проверенные радиопараметры

Это одиночные снимки в одном месте и при одном положении антенн; они не
заменяют длительный тест скорости.

| Оператор | LTE CA | RSRP | RSRQ | SINR | Потери ping |
|---|---|---:|---:|---:|---:|
| Beeline | B7+B20 | -105 dBm | -10 dB | 8 dB | 0% |
| MegaFon | B7+B7 | -95 dBm | -12 dB | 10 dB | 0% |
| T2 | B7+B3/B1 | -93 dBm | -9 dB | 11 dB | 0% |

## Итоговая минимальная конфигурация

```text
proto:  xmm
device: /dev/ttyACM0
APN:    пустой (Default APN оператора)
PDP:    IP
zone:   wan
```

При исправной физической SIM этого достаточно для обычных SIM Beeline,
MegaFon и T2 в проверенной сети.
